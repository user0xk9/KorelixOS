# Архитектура

## Порядок загрузки (`kernel/main.c`)

1. `serial_init`, `fb_init` — с этого момента `kprintf` пишет и в COM1, и на экран
2. `gdt_init`, `idt_init`
3. `pmm_init` (печатает карту памяти), `vmm_init` (свои таблицы страниц), `heap_init`
4. `pic_disable`, `acpi_init`, `lapic_init`, `ioapic_init`, `timer_init(100)`, `kbd_init`
5. `fpu_init`, `cpu_enable_protections` (SMEP/SMAP/UMIP), `syscall_init`, `sched_init`
6. модуль Limine `initrd.tar` → `vfs_init`, `initramfs_mount`
7. запуск `/bin/init` через `process_spawn`, `sti`, главный поток спит в `hlt`

## Карта виртуальной памяти

| Область | Адрес | Примечание |
| --- | --- | --- |
| Пользователь | `0x0 – 0x00007fffffffffff` | нижняя половина, у каждого процесса своя |
| Код процесса | от `0x400000` | ELF `ET_EXEC`, адреса ниже `0x10000` не отдаются |
| Стек процесса | вершина `0x00007ffffffff000`, 8 страниц | страница под стеком не отображена |
| HHDM | смещение от Limine | вся память кроме reserved/bad, страницы 2 МБ, `RW NX` |
| Куча ядра | `0xffffd00000000000`, до 1 ГБ | растёт по требованию |
| MMIO | `0xffffe00000000000` | без кэша, `NX` |
| Стеки ядра | `0xffffe80000000000` | 16 КБ + неотображённая guard-страница |
| Ядро | `0xffffffff80000000` | text `RX`, rodata `R NX`, data `RW NX` |

Верхняя половина PML4 общая у всех адресных пространств; её ветви создаются заранее в
`vmm_init`, поэтому новые процессы просто копируют записи.

## Модули

- **mm/pmm.c** — битовая карта физических страниц, обнаружение двойного освобождения
- **mm/vmm.c** — таблицы страниц, `vmm_map`/`vmm_unmap`/`vmm_translate`, `vmm_user_ok`
- **mm/heap.c** — список блоков с заголовком (magic), слияние соседей, отравление при `kfree`
- **sched/** — планировщик по кольцу задач, переключение контекста (`switch.asm`),
  `process_spawn` собирает адресное пространство, стек и `argc/argv`
- **syscall/** — вход по `syscall` (`syscall.asm`), диспетчер, `copy_*_user`
- **fs/** — VFS в памяти (дерево `vnode`, чтение и запись) и разбор tar (ustar), подробности ниже
- **exec/elf.c** — загрузчик ELF64
- **drivers/** — serial, PS/2, таймер LAPIC (калибровка по PIT), консоль, framebuffer

## Планировщик

Одно ядро (BSP). Таймер 100 Гц вызывает `schedule()`, задачи по кругу. Состояния:
`READY`, `RUNNING`, `SLEEPING`, `BLOCKED` (ждёт `wait`), `DEAD`. Завершённые задачи
освобождаются отложенно (`reap`). Состояние FPU/SSE сохраняется через `fxsave`/`fxrstor`
при каждом переключении. Есть задача `idle`.

## Файловая система

Дерево `vnode` в памяти. Каталог — список детей, у каждого узла есть `parent`, поэтому работают
`..` и относительные пути; у процесса есть рабочий каталог (`task->cwd`, `NULL` = корень).

- **Загрузка:** `initramfs_mount` разбирает tar и создаёт узлы; данные файлов остаются в модуле
  Limine (`owned = 0`). При первой записи содержимое копируется в кучу (copy-on-write), исходный
  образ не меняется.
- **Запись:** буфер растёт удвоением, запись за концом заполняет дыру нулями, размер файла
  ограничен `VFS_MAX_FILE` (8 МБ). Флаги `open`: `O_RDONLY/WRONLY/RDWR`, `O_CREAT`, `O_EXCL`,
  `O_TRUNC`, `O_APPEND`.
- **Имена:** компонент до 55 байт, путь до 255. Пути без `/` в начале считаются от cwd.
- **Каталоги:** `mkdir`, `rmdir` (только пустой и не занятый чьим-то cwd, иначе `EBUSY`),
  `rename` (файл заменяет файл; каталог нельзя перенести в самого себя; каталог поверх
  существующего — `EEXIST`).
- **Удаление открытого файла:** узел уходит из дерева, но живёт, пока есть ссылки (`refs`:
  открытые файлы и cwd процессов), и освобождается при последнем `close`.
- **Блокировка:** ядро вытесняемое, поэтому все операции идут под одной блокировкой
  `vfs_lock` (с запретом прерываний); данные копируются в пользовательскую память уже после
  освобождения блокировки, через буфер в ядре. `spawn` берёт копию исполняемого файла.
- **Ошибки:** вызовы возвращают `-errno` (`ENOENT`, `EEXIST`, `ENOTDIR`, ... см. `errno.h`).

Диска нет: всё живёт в памяти и теряется при перезагрузке.

Дескрипторы (`struct file`: узел, позиция, флаги, счётчик ссылок). fd 0, 1, 2 без файла означают
консоль; `spawn` передаёт ребёнку cwd и fd 0..2 родителя, а оболочка с помощью `in_fd/out_fd`
подставляет файлы для `<` и `>`.

## Системные вызовы

Номер в `rax`, аргументы `rdi rsi rdx r10 r8 r9`, результат в `rax` (при ошибке `-errno`);
`rcx` и `r11` портятся инструкцией `syscall`, остальные регистры сохраняются.

| № | Вызов | Описание |
| --- | --- | --- |
| 0 | `exit(code)` | завершить процесс |
| 1 | `write(fd, buf, len)` | файл или консоль (fd 1, 2); до 64 КБ за вызов, в консоль до 4 КБ |
| 2 | `getpid()` | |
| 3 | `sleep_ms(ms)` | |
| 4 | `open(path, flags)` | возвращает fd от 3 |
| 5 | `read(fd, buf, len)` | fd 0 без файла — строка с консоли; до 64 КБ за вызов |
| 6 | `close(fd)` | |
| 7 | `readdir(fd, index, *dirent)` | 1 — запись, 0 — конец |
| 8 | `spawn(path, argv, in_fd, out_fd)` | pid; `-1` = унаследовать stdin/stdout |
| 9 | `wait(pid, *status)` | ждёт завершения процесса |
| 10 | `mkdir(path)` | |
| 11 | `unlink(path)` | удалить файл |
| 12 | `rmdir(path)` | удалить пустой каталог |
| 13 | `rename(old, new)` | переименовать или перенести |
| 14 | `chdir(path)` | |
| 15 | `getcwd(buf, size)` | длина пути |
| 16 | `lseek(fd, off, whence)` | новая позиция |
| 17 | `stat(path, *stat)` | тип, размер, номер узла |
| 18 | `fsinfo(*info)` | число файлов, каталогов, байт |

Консольный stdin читает строку целиком (эхо, Backspace, Ctrl-D = конец ввода).

## Вывод на экран

`kprintf` и `kwrite` (его использует `write`) отправляют каждый байт в serial и в
`fbcon_putc` (`drivers/video/fb.c`).

- Режим: первый framebuffer от Limine, 32 бита на пиксель, RGB; другие режимы
  отключают экран (вывод остаётся в serial)
- Сетка: клетки 8×16, поля 8 пикселей, центровка
- Шрифт: `font8x16.h` (169 глифов: ASCII, русская и украинская кириллица),
  бинарный поиск по кодпоинтам; незнакомый символ рисуется как `?`
- Кодировка: UTF-8 разбирается автоматически, битые последовательности дают `?`
- Управляющие: `\n`, `\r`, `\b` (с переходом на предыдущую строку при переносе), `\t`;
  остальные игнорируются; ANSI-последовательности не поддерживаются
- Прокрутка: `memmove` содержимого на строку вверх
- Курсор: инвертированная клетка, рисуется в конце каждого вывода (`fbcon_flush`)
- Паника: дальнейший текст красным

Ограничения: память framebuffer отображена как обычная (write-back), на реальном
железе прокрутка может быть медленной (вариант улучшения: write-combining через PAT);
работа на реальном железе не проверялась.

## Тесты

`make test` собирает на хосте и запускает под ASan и UBSan (заглушка блокировки падает при повторном захвате):

- `test_string` — `memcpy`/`memset`/`memmove`/`memcmp` из `kernel/lib/string.c`
  (все варианты перекрытия против эталона)
- `test_initramfs` — разбор tar, включая усечённые и битые архивы
- `test_vfs` — пути, чтение и запись, copy-on-write, удаление открытых файлов, rename, ссылки
- `test_userland` — настоящие `sh`, `ls`, `cp`, `rm` и остальные команды поверх настоящего `vfs.c`,
  системные вызовы эмулирует `host_syscall`; слой `syscall.c` в этот тест не входит
- `test_fbcon` — отрисовка, UTF-8, перенос, прокрутка, курсор, крошечный экран

В QEMU тесты не запускаются; загрузка ядра проверяется вручную через `make run`.
